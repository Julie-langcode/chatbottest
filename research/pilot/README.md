# Пилот протокола управления галлюцинациями

Цель — получить собственные данные об ошибках ИИ-тренажёра: сколько ошибок и каких типов
он делает без протокола и с протоколом, на одних и тех же сценариях.

## Что понадобится

- Бот на Vercel с настроенными `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` (или локально: те же переменные в файле `.env`, см. `.env.example`)
- Node.js 18+; в папке проекта: `npm install`, затем `npm run dev`, открыть `http://localhost:5173`
- Файл сценариев: [`scenarios.md`](scenarios.md)
- Инструкция по разметке: [`annotation-guide.md`](annotation-guide.md)
- Скрипт подсчёта: [`analyze.py`](analyze.py) (Python 3, без внешних библиотек)

## Условия

| Условие | Как включить | Что работает |
|---|---|---|
| **A — без протокола** (базовая линия) | Внизу стартового экрана: «Исследование и журнал сессий» → снять галочку протокола. Или открыть `http://localhost:5173/?protocol=off` | Исходные промпты режимов |
| **B — с протоколом** | Галочка включена (по умолчанию) | Уровень 1 (правила + словарь курса в промпте) и уровень 2 (проверочный вызов после каждого ответа) |

Каждая сессия в журнале помечена условием, версией протокола и версией промптов.

## Порядок

1. **Минимум до 23.10:** сценарии P1, P2, O1, N1, V1, F1 в условии A (6 сессий, ~40 минут).
   Этого достаточно, чтобы привести в докладе реальные примеры ошибок вместо иллюстративных.
2. **Полный пилот (ноябрь):** все 25 сценариев в условиях A и B — 50 сессий.
   Порядок условий чередуй: нечётные сценарии сначала A, чётные сначала B.
3. Реплики «обучающегося» вводи **дословно** из `scenarios.md`, по одной на ход. Ничего не
   добавляй от себя — иначе условия станут несравнимыми.
4. Во время сессии **не нажимай** «Ошибка ИИ?»: в пилоте ты исследователь, а не обучающийся.
   Кнопку и блок «Проверь ИИ» проверяем отдельно, на пользователях.
5. После всех сессий: «Исследование и журнал сессий» → **CSV для разметки** и
   **Полный журнал (JSON)**. Сохрани оба файла.

## Этап 2: перепроверка журнала (уровень 2 на тех же ответах)

Чтобы отделить работу проверочного вызова от случайности модели, его применяют к тем же
ответам условия A, которые уже размечены вручную.

1. На том же компьютере и в том же браузере, где записаны сессии A: «Исследование и журнал
   сессий» → **Перепроверить журнал**. Дождаться «Проверено N из N» (около 30 с на 30 ответов).
   Если часть проверок не прошла, нажать кнопку ещё раз: проверятся только оставшиеся.
2. **CSV перепроверки** → сохранить файл.
3. Подсчёт: `python3 research/pilot/analyze.py recheck annotated.csv recheck.csv` — сколько
   ошибок по содержанию поймано (recall), сколько ложных тревог (precision), список пропусков.

## Разметка

1. Открой CSV в Excel или Google Таблицах.
2. Размечай только строки `role = assistant` (ответы ИИ), по [`annotation-guide.md`](annotation-guide.md):
   колонки `annot_error_yes_no`, `annot_error_type`, `annot_quote`, `annot_note`, `annot_rater`.
3. **Слепая разметка:** перед разметкой скрой колонки `protocol`, `checker_status`, `checker_issues`,
   чтобы не знать условие.
4. Для надёжности второй разметчик (коллега-преподаватель) независимо размечает копию того же файла
   хотя бы для 20% ответов.

## Подсчёт

```bash
python3 research/pilot/analyze.py summary annotated.csv
python3 research/pilot/analyze.py kappa rater1.csv rater2.csv
```

`summary` — ошибки по типам и условиям, доля ответов с ошибкой, совпадение с проверочным вызовом.
`kappa` — согласованность двух разметчиков (каппа Коэна) по наличию и по типу ошибки.

## Этика и данные

- В пилоте реплики «обучающегося» — заготовленные тексты, персональных данных нет.
- На этапе апробации с участниками: информированное согласие, обезличивание выгрузок,
  хранение файлов вне публичного репозитория. **Не коммить выгрузки с реальными диалогами в Git.**
